# A lightweight hackathon workflow

## Start with a shared target

Write one sentence: “For [user], this project makes [task] easier by [working behavior].” Agree on the demo before splitting work. Keep one must-have flow; put optional ideas in a separate list.

## Own small pieces

Use the task issue form for each independently reviewable piece. Give it an owner, an observable acceptance check, and any dependency. Suggested board columns: **Backlog → Ready → Building → Review → Done**. The board is optional; a short issue list is enough for a small team.

## Integrate early

Connect the frontend and backend before polishing. Agree on sample input/output and error responses. Keep branches focused and bring working pieces together regularly. Do not wait until the final hour to test the full flow.

## Define done

A task is done when the acceptance check passes, the change is integrated, setup information is current, and the demo can use it. A teammate should be able to explain any remaining limitation.

## Reserve time for delivery

Choose a feature freeze that leaves time to test a clean setup, record a demo, check access, and complete the submission form. Cut optional scope when the core flow is at risk.
