# Submission checklist

## Event fit

- [ ] The project follows the event rules, theme, and selected prize track.
- [ ] Team eligibility, size, and submission deadline are confirmed.
- [ ] Pre-existing code, templates, models, and AI assistance are disclosed as required.
- [ ] The README describes implemented features separately from future plans.

## Review access

- [ ] Judges can access the repository with the visibility required by the event.
- [ ] The demo and video links work in a signed-out browser.
- [ ] Necessary demo access uses appropriate sample accounts/data.
- [ ] No credentials, personal data, or local-only file paths are published.
- [ ] Screenshots have useful alt text and video text is readable.

## Reproducibility

- [ ] Setup was followed from a clean checkout.
- [ ] Runtime versions, environment variable names, and external services are documented.
- [ ] The main user flow was exercised and its known limits are documented.
- [ ] The real test command and evidence are included.
- [ ] The default branch contains the intended submission version.

## Presentation

- [ ] The demo shows the core flow and fits the allowed time.
- [ ] There is a recording or screenshot fallback.
- [ ] Each team member's contribution and all external assets are credited.
- [ ] The submission page, repository, and video use consistent project naming.
- [ ] The final submission is saved and the confirmation is checked before the deadline.
